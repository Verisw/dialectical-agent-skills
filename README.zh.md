# dialectical-agent-skills

**两个面向 AI Agent 的通用认知框架 Skill，提供中英双语版本。**

这两个 Skill 将经典辩证唯物主义哲学中的两大核心认识论与分析法，以现代系统论和认知科学术语重新建模，形成可直接接入 Agent 的 `SKILL.md` 规范文件。

适用范围：**任何领域** — 软件系统工程、科学研究、商业战略、组织治理，乃至一切需要实证推理与结构化问题分解的分析场景。

---

## Skill 目录

| Skill | 触发条件 | 核心机制 |
|---|---|---|
| [`on-practice`](skills/on-practice/) | 探索未知领域、形成与检验假说、需要实证接地而非空想盲动 | 四阶段实证闭环 + 领域适配协议 |
| [`on-contradiction`](skills/on-contradiction/) | 复杂情境分析、根因诊断、战略取舍决策、多重矛盾冲突疏解 | 四维矛盾解剖框架 + 领域适配协议 |

---

## 架构：双层设计

两个 Skill 共享同一套**双层架构**：

```
Tier 1: 顶层不变指导思想（领域无关，永不改变）
         ↓  标准四槽位适配接口
Tier 2: 领域适配层（面向特定垂直领域的可插拔适配剖面）
```

**Tier 1** 建立普遍适用的不变性哲学公理。  
**Tier 2** 提供标准化的四槽位适配接口，让 Agent 可以在任何新领域中即时实例化该协议。

## Skill 一：`on-practice` — 知行探索与实证验证协议

**加载时机：** 探索未知情境、获取新领域知识、基于现实形成并检验假说、需要实证接地而非投机推断或盲目行动时。

### Tier 1：顶层不变原则

| 公理 | 操作规范 |
|---|---|
| **反对教条主义** | 未接触客观一手事实，不得做出任何主观断言。拒绝单纯依赖缓存的先验假设或二手摘要进行推理。 |
| **反对狭隘经验主义** | 缺乏抽象与理论加工的低水平忙碌不是有效实践。原始经验必须提炼为可迁移的因果模型。 |
| **实践是检验真理的唯一标准** | 内部置信度与推演逻辑的优美，不是真理判定标准。唯有客观世界的反作用力能验证一个主张。 |

### 四阶段实证闭环

```
[客观现实 / 待解领域]
         │
         ▼  获取第一手、未经中介的客观事实
[阶段一：感性认识（Sensory Grounding）]
         │
         ▼  去噪 → 提炼核心 → 横向联结 → 穿透机制
[阶段二：认知抽象（Cognitive Distillation）← 第一次飞跃：感性 → 理性]
         │
         ▼  带着假说/方案主动介入客观现实
[阶段三：主动实践检验（Active Reality Testing）← 第二次飞跃（关键跃迁）]
         │
         ├─ [验证成立] ──→ 形成相对真理；指导更大规模行动
         │
         └─ [暴露偏差] ──→ 客观反馈揭示主观局限性
                                   │
                                   ▼
                      [阶段四：螺旋校准（Spiral Recalibration）]
                                   │
                                   └─→ 更新认知模型；在更高精度上开启新一轮循环
```

> **不变规则：** 未获得阶段三的客观证据，不得宣称命题已被解决。阶段二内部的逻辑完备性是必要条件，但不是充分条件。

### Tier 2：领域适配协议（4 个槽位）

| 适配槽位 | 核心提问 | 规范定义 |
|---|---|---|
| **Slot 1 — 调查源（Sensory Source）** | 该领域的"第一手客观事实"是什么？ | 确定原始数据渠道；绕过二手解读与综合报告。 |
| **Slot 2 — 领域蒸馏（Domain Distillation）** | 该领域如何去噪、暴露机制、横向联结？ | 命名领域专属噪音模式、常见伪命题、横向类比与因果深度指标。 |
| **Slot 3 — 实践场（Practice Medium）** | 检验领域的具体场所是什么？真理硬性标准是什么？ | 指定部署目标与客观量化成功指标。 |
| **Slot 4 — 校准信号（Calibration Signals）** | 哪些可观测信号表明 Agent 的模型已偏离现实？ | 列出必须触发模型更新并重回阶段一的具体失败特征。 |

### 预置领域适配剖面

<details>
<summary><strong>软件与系统工程</strong></summary>

- **Slot 1（调查源）：** 运行时真实环境配置、未截断的系统日志、最小可复现脚本、生产可观测性指标——禁止假设版本或依赖状态。
- **Slot 2（蒸馏）：** 剥离无关堆栈帧；消除偶发缓存伪命题；追溯上游配置漂移与近期变更；定位竞争条件、资源泄漏与不变性破坏点。
- **Slot 3（实践场）：** 编译运行；单元/集成/端到端测试套件。**真理标准：** Exit code 0，所有断言绿色，目标指标平稳。
- **Slot 4（校准信号）：** 测试报错、内存激增、死锁、CI 抖动 → 提示某个环境假设或边界条件有误。

</details>

<details>
<summary><strong>科学研究</strong></summary>

- **Slot 1（调查源）：** 仪器采集的未处理原始读数；未清洗的实验数据集；一手文献的方法章节——非综述摘要。
- **Slot 2（蒸馏）：** 去除仪器基线漂移；识别伪相关与幸存者偏差；从第一原理出发构建机理模型。
- **Slot 3（实践场）：** 盲法受控对照实验；可复现性压力测试；对抗性同行复现验证。**真理标准：** 实验严格可复现；预测值与新独立测量吻合。
- **Slot 4（校准信号）：** 反常观测、统计显著性消失 → 提示某个基础理论假设在极端边界处失效。

</details>

<details>
<summary><strong>商业战略</strong></summary>

- **Slot 1（调查源）：** 未经过滤的客户访谈原声；真实现金流与留存漏斗数据；供应商/渠道一线实地体感——而非美化的汇报材料。
- **Slot 2（蒸馏）：** 过滤 PR 层虚荣指标；区分"口头宣称想要"与"真实付费意愿"的落差；比对行业生命周期阶段与跨品类演进路径。
- **Slot 3（实践场）：** MVP 试水；定向定价实验；真实商业闭环结算。**真理标准：** 自然留存率与来自真实交易的正净现金流。
- **Slot 4（校准信号）：** 高 CAC、低 LTV、内部推行阻力 → 提示用户需求或商业模式假设存在主观偏差。

</details>

<details>
<summary><strong>组织治理</strong></summary>

- **Slot 1（调查源）：** 一线基层员工匿名反馈；端到端交付实际周期测量；决策审计日志——而非经过过滤的中层汇报。
- **Slot 2（蒸馏）：** 将情绪宣泄与系统性流程堵点分离；识别制度规定流程与人们实际遵循的隐性流程之间的落差。
- **Slot 3（实践场）：** 在隔离的团队或部门试点机制调整。**真理标准：** 端到端交付时效提升幅度与基层主动性数据。
- **Slot 4（校准信号）：** 推诿扯皮、政策下有对策、核心人才流失 → 提示激励机制错位或制度设计产生逆向激励。

</details>

### 新领域适配指南

面对未知新领域时，在首轮推理中声明此适配剖面：

```markdown
### 领域认知映射声明（Domain Adaptation Profile: [领域名称]）
1. 调查源（Sensory Source）：我将通过 [具体第一手数据渠道] 获取客观事实；
   我不会单纯依赖二手摘要进行推理。
2. 领域蒸馏（Domain Distillation）：在该领域，我需特别过滤的噪音是 [X]；
   我将着重追溯的底层因果机制是 [Y]。
3. 实践场（Practice Medium）：我将把假说投放至 [具体部署目标] 接受检验；
   真理硬性标准为 [量化客观指标]。
4. 校准信号（Calibration Signals）：一旦观察到 [特定负反馈模式]，
   我将立即修正认知模型并重回阶段一。
```

## Skill 二：`on-contradiction` — 矛盾解剖与根因决断协议

**加载时机：** 分析复杂情境、诊断系统性问题根因、在相互竞争的优先级之间进行权衡决断、或在任何领域中疏解多重冲突时。

### Tier 1：顶层不变原则

| 公理 | 操作规范 |
|---|---|
| **矛盾的普遍性** | 任何复杂系统中的摩擦、瓶颈与危机不是意外，而是内在结构性张力的必然激化。将其视为信号，而非偶发事故。 |
| **矛盾的特殊性** | 不同性质的矛盾，只有用不同质的方法才能解决。禁止套用模板方案；必须具体问题具体分析。 |
| **牵住主要矛盾** | 在任何乱局中，必有一种矛盾统领和制约其他矛盾。解决主要矛盾，次要矛盾将迎刃而解；仅修复次要矛盾，系统依然破败。 |
| **辨明矛盾的主要方面** | 在任何二元取舍中，当前阶段必有一方处于支配地位。明确指出哪方，并据此行动。拒绝平庸的折中和稀泥方案。 |
| **动态转化预警** | 条件变化后，今日的优势可能成为明日的包袱。预判在何种条件下当前解法会反转为新的问题。 |

### 四维矛盾解剖框架

```
[复杂危机 / 杂乱表象 / 相互冲突的诉求]
                  │
                  ▼
维度一：矛盾的特殊性（Qualitative Particularity）
  — 在本情境中，这个矛盾具有怎样不可替代的特殊性质？
  — 拒绝泛化标签；命名精确的结构性类型。
                  │
                  ▼
维度二：主要矛盾 vs 次要矛盾（Principal vs Secondary）
  — 构建因果传导链。
  — 剥离次生表象；锁定统领全局的"牛鼻子"。
  — 将 80% 的资源集中打在主要矛盾上。
                  │
                  ▼
维度三：矛盾的主要方面（Dominant Aspect & Trade-off）
  — 在核心二元张力中，当前阶段哪一方必须占据支配地位？
  — 明确陈述阶段性理由。拒绝各打五十大板。
                  │
                  ▼
维度四：动态转化与反噬预警（Transformation Dynamics）
  — 在何种边界条件下，当前解法会反转为新的危机？
  — 设置明确的预警触发条件，并定义对冲机制。
```

### Tier 2：领域适配协议（4 个槽位）

| 适配槽位 | 核心提问 | 规范定义 |
|---|---|---|
| **Slot 1 — 矛盾性质（Nature）** | 该领域中的矛盾通常以哪几种形态呈现？ | 识别领域专属冲突原型；拒绝表面化的泛化标签。 |
| **Slot 2 — 牛鼻子（Linchpin）** | 该领域中如何区分根因矛盾与次生表象？ | 构建因果传导判定链；将资源集中于真正的主要矛盾。 |
| **Slot 3 — 取舍权衡（Trade-off）** | 该领域的经典二元张力是什么？如何判断特定阶段的主要方面？ | 明确当前阶段哪种价值必须优先，以及原因。 |
| **Slot 4 — 反噬防范（Reversal Guard）** | 在何种条件下，有效的解法会变成系统性风险？ | 定义适用边界、规模拐点与对冲机制。 |

### 预置领域适配剖面

<details>
<summary><strong>软件与系统工程</strong></summary>

- **Slot 1（矛盾性质）：** 时序矛盾（并发竞争、死锁、时钟漂移）；资源矛盾（连接池耗尽、I/O 争用）；契约矛盾（API 协议漂移、跨服务语义断裂）。
- **Slot 2（牛鼻子）：** 在连锁错误事件中，溯源最早破坏系统状态不变性的事件。之后的一切都是次生表象。（示例：DB 连接泄漏 → Worker 挂起 → 网关 502。主要矛盾在连接释放逻辑，网关超时是次生矛盾。）
- **Slot 3（取舍权衡）：** CAP 定理、吞吐量 vs 延迟、性能 vs 可维护性。在核心结算链路，**正确性**是主要方面；在边缘日志链路，**吞吐量**可能占主要方面。阶段（早期开发 vs 生产规模）决定主要方面。
- **Slot 4（反噬防范）：** 粗粒度互斥锁（短期解法）在并发量跨过阈值后，必然成为全局吞吐瓶颈。激进缓存（延迟优化）在写入频繁时，必然转化为缓存一致性与内存压力危机。

</details>

<details>
<summary><strong>科学研究</strong></summary>

- **Slot 1（矛盾性质）：** 范式矛盾（经典理论预测 vs 反常实验测量）；仪器矛盾（观测装置噪声 vs 微弱信号检测）；泛化矛盾（理想实验室条件 vs 自然界复杂扰动）。
- **Slot 2（牛鼻子）：** 在解释一系列反常数据时，核心在于判断：统治性矛盾是仪器系统误差（次要），还是基础理论公设在极端边界处失效（主要）。
- **Slot 3（取舍权衡）：** 模型解释力 vs 模型复杂度（奥卡姆剃刀）。探索初期：**可解释性与可证伪性**是主要方面。工程应用期：**计算可行性与鲁棒性**上升为主要方面。
- **Slot 4（反噬防范）：** 通过增加无约束自由参数强行拟合异常值，训练误差低，但面对新样本时过拟合发作，可复现性崩溃。

</details>

<details>
<summary><strong>商业战略</strong></summary>

- **Slot 1（矛盾性质）：** 存量营收 vs 新增长矛盾（业务组合蚕食）；价值创造 vs 价值攫取矛盾（平台生态健康 vs 商业化变现）；规模 vs 单位效率矛盾。
- **Slot 2（牛鼻子）：** 当公司同时面临营收下滑、内部动荡和竞品夹击时，主要矛盾通常是核心产品-市场契合度（PMF）的衰减，管理摩擦只是次生症状。
- **Slot 3（取舍权衡）：** 速度 vs 盈利；集权 vs 分权。生死破局期：**增速**是主要方面。市场存量出清期：**正向自由现金流**上升为主要方面。
- **Slot 4（反噬防范）：** 在留存尚未成立前依靠高额补贴买增长，会产生"补贴依赖型用户"——补贴一停，用户即散，资金链随之断裂。

</details>

<details>
<summary><strong>组织治理</strong></summary>

- **Slot 1（矛盾性质）：** 集权管控 vs 一线活力矛盾；制度刚性 vs 人性适应性矛盾；局部单元利益 vs 全局战略协同矛盾。
- **Slot 2（牛鼻子）：** 部门间持续的推诿扯皮是次生表象；主要矛盾通常是考核指标的零和博弈设计——A 部门 KPI 达成直接损害 B 部门利益。
- **Slot 3（取舍权衡）：** 合规风控 vs 创新容错。成熟业务线：**流程合规**是主要方面。创新孵化特区：**敏捷试错与容错**必须是主要方面。
- **Slot 4（反噬防范）：** 为防范极少数违规而制定繁苛审批流程，必然在全员层面异化为官僚主义推诿与组织决策瘫痪——以多数人的效率为极少数人的潜在违规买单。

</details>

### 新领域适配指南

分析任何新领域前，在推理中声明此适配剖面：

```markdown
### 领域矛盾解剖声明（Domain Contradiction Profile: [领域名称]）
1. 矛盾性质（Nature）：本情境的核心矛盾属于 [领域专属冲突原型]。
2. 主要矛盾定位（Linchpin）：在表象症状 [A、B、C] 中，统领全局的根因矛盾是 [X]，
   因为 [因果传导链]。
3. 取舍主次决断（Dominant Aspect）：面临 [二元取舍] 时，当前阶段必须以 [主要方面]
   为支配考量，因为 [阶段性理由]。
4. 反噬防范（Reversal Guardrail）：当 [边界条件] 满足时，当前策略可能发生负面反转；
   对冲机制为 [应对预案]。
```
